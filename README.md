# STC — Steering Turret Controller

## 1. Project scope
STC (Steering Turret Controller) provides a server, command-line tools, telemetry receivers, optional Qt diagnostics GUI, and bench/test executables for turret and actuator control workflows over TCP/UDP/CAN.

This README is the authoritative operational guide for build, deployment, bench bring-up, diagnostics, and protocol usage.

## 2. Repository layout
- `CMakeLists.txt`: top-level build configuration.
- `src/`: server and core runtime logic.
- `include/`: public/internal headers used by project targets.
- `dev/`: bench configs, scripts, and test assets (non-authoritative docs removed; this root README is canonical).
- `deploy/`: systemd unit files and deployment helpers.
- `scripts/`: utility scripts (including virtual CAN setup helpers where available).
- `build/`: out-of-source build artifacts (generated).
- `logs/`: runtime telemetry/CAN/GUI capture output (generated by workflows below).

## 3. Supported runtime modes
- Hardware CAN runtime (`USE_SIMULATOR=OFF`).
- Simulator runtime (`USE_SIMULATOR=ON`).
- Server-only operation (`stc_server`).
- Server + CLI (`icd_tx_tcp`, `tlm_rx_udp`).
- Server + Qt diagnostics GUI (`diag_gui_qt`, if built).
- Standalone X8 bench test binary (`x8_25_test_can`).

## 4. Dependencies and packages
Core requirements:
- Linux environment (SocketCAN workflows are Linux-native).
- CMake >= 3.16.
- C11/C++17 toolchain (GCC/G++ recommended).
- Build backend (`make` or `ninja`).

Optional/runtime packages:
- Qt6 (`Core`, `Gui`, `Widgets`, `Network`) for `diag_gui_qt`.

## Runtime backend vs axis motor driver

The server has two layers:

1. Runtime backend:
   - `simulator`: no real hardware
   - `hardware_can` / `can`: real CAN bus

2. Per-axis motor driver:
   - `pd4c`: Nanotec PD4-C CANopen/DS402
   - `myact_x8_25`: MYACTUATOR X8 protocol
   - `disabled`: unmapped axis

`--backend can` means “use real CAN hardware.” It does not mean PD4C.
The actual motor library and command semantics are selected per axis in `[AxisN].driver`.

Mixed example:

```ini
[Axis0]
enabled=true
driver=pd4c
node_id=1
role=turret_az

[Axis1]
enabled=true
driver=myact_x8_25
node_id=2
role=mirror1

## 16. Troubleshooting
- `diag_gui_qt` missing: rebuild with `-DBUILD_DIAG_GUI=ON` and ensure Qt6 packages are installed.
- CAN link issues: re-run CAN setup commands and verify `ip -details -statistics link show can0`.
- No telemetry seen: confirm server is running, UDP ports (6010/6020) are reachable, and receiver commands are bound as expected.
- Command failures: verify TCP endpoint (`127.0.0.1:7000`) and CU mode transitions (`cu_state` commands).
- Warning audit: run the warning check command block from Section 5 and inspect `/tmp/stc_build.log`.

## 17. TLML/TLMH protocol summary
### TLMH high-rate telemetry

Default rate: 100 Hz  
Default port: 6010  
Canonical axis count: 18

Payload:
- position[18] float
- rates[18] float
- acceleration[18] float

### TLML low-rate telemetry

Default rate: 10 Hz  
Default port: 6020  
Base size before diagnostics: 100 bytes

Payload includes:
- state
- uptime
- environment fields
- WGS84/manual position fields
- heading
- motor_status[18]
- laser_status[8]
- level_x / level_y
- error_count
- diagnostics array

motor_status[18] follows the canonical motor axis order:
0 ST az
1 ST el
2 SUT1 az
3 SUT1 el
...
16 SUT8 az
17 SUT8 el

laser_status[8] follows:
0 SUT1 laser
...
7 SUT8 laser

Laser hardware is currently stubbed. Values represent commanded software state only unless real laser hardware is integrated.
